Este guia explica todos os conceitos usados no projeto A-Maze-ing, do zero: pressupõe que você nunca programou e está vendo Python pela primeira vez. Cada conceito segue o mesmo roteiro:

  1. Em uma frase o que é, sem jargão;
  2. Analogia uma comparação com o dia a dia;
  3. um exemplo curto de Python, com a saída (todos foram executados para conferir);
  4. No projeto onde aparece no código real;
  5. Erro comum o que costuma dar errado;
  6. Teste rápido: tente responder antes de abrir a resposta.
Como estudar: siga a ordem dos módulos (1 a 12), rode os exemplos no seu computador (copie para um arquivo .py ou use o modo interativo do python3) e use as animações dos módulos 8 e 10. Marque cada módulo como lido na barra lateral. Na defesa, você precisará explicar o código, e não apenas mostrá-lo.

3. GeraMazeGenerator cria o labirinto (DFS, e braiding se não for perfeito)
→
4. ResolveBFS acha o caminho mais curto
→
5. Salvaum dígito hex por célula, entrada, saída, caminho

Módulo 1. Antes do código

Antes de escrever uma linha, você precisa saber o que é um programa e como conversar com o computador. Este módulo não exige nenhum conhecimento prévio.

1.1O que é um programa

Em uma frase Uma lista de instruções que o computador executa, uma depois da outra.

Analogia Uma receita de bolo. O computador é um cozinheiro muito literal: faz exatamente o que está escrito, na ordem escrita, sem adivinhar a intenção.

# Um programa de 3 instruções
print("Olá!")
print("Vamos criar um labirinto")
print("Fim")
Saída
Olá!
Vamos criar um labirinto
Fim

No projeto a_maze_ing.py é o programa inteiro: lê a configuração, gera o labirinto, salva o arquivo e mostra o menu, nessa ordem.

Erro comum Achar que o computador "entende o que você quis dizer". Uma letra errada muda tudo, e o programa só faz o que foi escrito.

Teste rápido: Por que a ordem das instruções importa?

Porque elas rodam de cima para baixo. Usar algo antes de criá-lo, por exemplo, dá erro.

1.2Terminal e comandos

Em uma frase Uma janela onde você dá ordens ao computador digitando texto.

Analogia Trocar mensagens de texto com o computador: você escreve um comando, ele responde.

pwd              # onde estou? (mostra a pasta atual)
ls               # o que existe aqui?
cd amazeing      # entra na pasta "amazeing"
cd ..            # volta uma pasta

No projeto Tudo no projeto é rodado no terminal: make run, python3 a_maze_ing.py config.txt, make lint.

Erro comum command not found quase sempre é erro de digitação ou programa não instalado. No such file or directory é pasta errada: use pwd e ls para se localizar.

Teste rápido: O que faz cd ..?

Volta para a pasta de cima (a pasta "pai").

1.3O interpretador Python

Em uma frase O programa que lê um arquivo .py e executa as instruções dele.

Analogia Um intérprete simultâneo: ouve uma frase em Python, traduz e executa na hora, frase por frase.

python3 --version     # mostra a versão instalada
python3               # abre o modo interativo (>>>); saia com Ctrl+D

No projeto O projeto exige Python 3.10 ou mais novo, porque usa escritas como int | None e list[int].

Erro comum Usar python em vez de python3 (em alguns computadores python é a versão 2 ou nem existe), ou uma versão antiga demais.

Teste rápido: Para que serve o modo interativo (>>>)?

Para testar uma linha de Python e ver o resultado na hora, sem criar arquivo.

1.4Rodar um script

Em uma frase Pedir ao interpretador que execute um arquivo .py, entregando a ele, se preciso, argumentos.

Analogia Abrir um programa e entregar um documento para ele abrir.

python3 a_maze_ing.py config.txt
#  |        |            |
#  |        |            +-- argumento: o arquivo de configuração
#  |        +--------------- o script (nosso programa)
#  +------------------------ o interpretador

No projeto É exatamente o comando exigido pelo enunciado. O programa recebe só o nome da configuração.

Erro comum Rodar de outra pasta: o Python não acha a_maze_ing.py nem config.txt. Confira com ls.

Teste rápido: Se esqueço o config.txt, o que acontece no nosso programa?

Ele imprime a mensagem de uso (Usage: python3 a_maze_ing.py config.txt) e termina com código 2, sem quebrar.

1.5Arquivos, pastas e caminhos

Em uma frase Um arquivo guarda dados; um caminho diz onde ele está.

Analogia Caminho absoluto é o endereço completo da casa ("Rua X, 10"); caminho relativo é "a segunda porta à direita", que depende de onde você está.

/Users/ana/amazeing/maze.txt   # absoluto: funciona de qualquer lugar
maze.txt                      # relativo: na pasta onde o programa roda
tests/helpers.py              # relativo: dentro da subpasta tests

No projeto OUTPUT_FILE=maze.txt é relativo: o arquivo nasce na pasta onde você rodou o programa.

Erro comum Dizer que o arquivo "sumiu": ele foi criado em outra pasta, a atual no momento da execução.

Teste rápido: O que é um arquivo de texto?

Um arquivo cujo conteúdo são só caracteres legíveis, como o config.txt e o arquivo do labirinto.

Módulo 2. Python básico

Os blocos de construção de qualquer programa: guardar valores, decidir e repetir.

2.1Variáveis

Em uma frase Um nome que guarda um valor.

Analogia Uma etiqueta colada numa caixa: a caixa guarda o valor, a etiqueta é o nome pelo qual você chama.

width = 20
height = 15
cells = width * height
print(cells)
Saída
300

No projeto No MazeGenerator.__init__: self.width = width guarda o valor recebido para usar depois.

Erro comum Confundir = (guardar um valor) com == (comparar). Usar um nome antes de criá-lo dá NameError.

Teste rápido: Depois de x = 5 e x = x + 1, quanto vale x?

6. Primeiro calcula-se o lado direito (5 + 1) e o resultado volta para x.

2.2Tipos de dados

Em uma frase Cada valor tem um tipo que diz o que ele é e o que dá para fazer com ele.

Analogia Recipientes diferentes para coisas diferentes: copo para líquido, caixa para objetos. Número soma; texto junta.

width = 20            # int: número inteiro
name = "maze.txt"     # str: texto
perfect = True        # bool: verdadeiro ou falso
seed = None           # None: "nenhum valor"
print(type(width), type(perfect))
Saída
<class 'int'> <class 'bool'>

No projeto MazeConfig declara width: int, output_file: str, perfect: bool e seed: int | None.

Erro comum Tudo o que vem de um arquivo é texto. "20" + 1 dá erro; é preciso converter com int("20").

Teste rápido: Qual o tipo de "20" (com aspas)?

str (texto), não número.

2.3Operadores

Em uma frase Símbolos que calculam ou comparam: + - * / // % == != < > and or not.

Analogia Os botões de uma calculadora, mais perguntas de sim ou não ("3 é menor que 5?").

print(7 // 2)                # divisão inteira
print(7 % 2)                 # resto da divisão
print(7 / 2)                 # divisão comum
print(3 < 5 and 2 == 2)      # as duas coisas são verdade?
Saída
3
1
3.5
True

No projeto width % 2 diz se a largura é ímpar; (width - block_width) // 2 centraliza o "42" (em mazegen/pattern.py).

Erro comum / sempre devolve número com vírgula (float). Para posições em grade use //.

Teste rápido: Quanto é 20 % 2 e o que isso significa?

0: não sobra resto, então 20 é par.

2.4Textos (str) e f-strings

Em uma frase Texto fica entre aspas; uma f-string deixa encaixar valores dentro dele com {...}.

Analogia Um formulário com lacunas: "Entrada: ___,___", e o Python preenche.

x, y = 3, 4
print(f"Entrada: {x},{y}")
print("Linha 1\nLinha 2")      # \n = quebra de linha
line = "  width = 20  "
print(line.strip().upper())    # tira espaços e põe em maiúsculas
Saída
Entrada: 3,4
Linha 1
Linha 2
WIDTH = 20

No projeto format_maze monta o arquivo de saída com f-strings: f"{maze.entry[0]},{maze.entry[1]}\n".

Erro comum Esquecer o f antes das aspas: o programa imprime {x} literalmente.

Teste rápido: O que "a,b".split(",") devolve?

Uma lista: ['a', 'b']. É assim que separamos x,y nas coordenadas.

2.5Decisões: if / elif / else

Em uma frase Executa um bloco só se uma condição for verdadeira.

Analogia Uma bifurcação: "se estiver chovendo, leve guarda-chuva; senão, óculos de sol".

width = 250
if width < 1:
    print("pequeno demais")
elif width > 200:
    print("grande demais")
else:
    print("ok")
Saída
grande demais

No projeto _parse_size em app/config.py recusa tamanhos fora de 1 a 200; run_menu escolhe a ação pela tecla digitada.

Erro comum Esquecer os dois-pontos : no fim da linha ou errar a indentação (SyntaxError).

Teste rápido: Quando o else executa?

Quando nenhuma das condições anteriores (if e elif) foi verdadeira.

2.6Repetição: for, while e range

Em uma frase for repete para cada item; while repete enquanto uma condição valer.

Analogia for: "para cada prato da pilha, lave". while: "enquanto houver prato sujo, lave".

for y in range(2):          # y = 0, 1
    for x in range(3):      # x = 0, 1, 2
        print(f"({x},{y})", end=" ")
    print()                 # pula de linha ao fim de cada linha
Saída
(0,0) (1,0) (2,0) 
(0,1) (1,1) (2,1)

No projeto Percorrer toda a grade: for y in range(self.height): for x in range(self.width). O DFS usa while stack: e o menu usa while True:.

Erro comum range(3) vai de 0 a 2 (não inclui o 3). Um while cuja condição nunca muda roda para sempre: pare com Ctrl+C.

Teste rápido: O que range(1, 4) gera?

1, 2 e 3 (o limite final não entra).

2.7Indentação e blocos

Em uma frase Em Python, o recuo (4 espaços) define quais linhas pertencem a um bloco.

Analogia Itens e subitens de uma lista: o recuo mostra o que está dentro de quê.

for n in range(3):
    if n == 1:
        print("meio")      # dentro do if, dentro do for
    print("fim da volta")  # só dentro do for
print("acabou")            # fora de tudo
Saída
fim da volta
meio
fim da volta
fim da volta
acabou

No projeto Em todo o código. O flake8 reclama de recuos irregulares.

Erro comum Misturar tab com espaços ou recuar com quantidades diferentes: IndentationError.

Teste rápido: No exemplo, quantas vezes aparece "fim da volta"?

3, uma por volta do for.

Módulo 3. Coleções

Como guardar muitos valores juntos. O labirinto inteiro é uma coleção de coleções.

3.1Listas

Em uma frase Uma sequência ordenada e alterável de valores.

Analogia Uma fila de caixinhas numeradas a partir do zero.

dirs = ["N", "E", "S", "W"]
dirs.append("X")                    # adiciona no fim
print(dirs[0], len(dirs), dirs[-1])   # primeiro, tamanho, último
Saída
N 5 X

No projeto stack = [self.entry], stack.append(...) e stack.pop() no DFS; o caminho (solve_cells) é uma lista de células.

Erro comum Os índices começam em 0: numa lista de 4 itens o último é [3]; [4] dá IndexError.

Teste rápido: Em dirs acima (antes do append), quanto é dirs[1]?

"E", porque o primeiro é o índice 0.

3.2Lista de listas: a grade do labirinto

Em uma frase Uma lista cujos itens são listas, formando linhas e colunas.

Analogia Uma planilha: primeiro escolhe a linha, depois a coluna.

grid = [[15] * 3 for _ in range(2)]   # 2 linhas x 3 colunas
grid[1][2] = 7                        # linha 1, coluna 2
print(grid)
Saída
[[15, 15, 15], [15, 15, 7]]

No projeto self.grid = [[ALL_WALLS] * self.width for _ in range(self.height)]. Acessamos a célula (x, y) como grid[y][x]: linha primeiro.

Erro comum [[0]*3]*2 cria duas linhas que são a mesma lista: mudar uma muda a outra. Por isso usamos a construção com for.

Teste rápido: A célula x=5, y=2 é grid[2][5] ou grid[5][2]?

grid[2][5]: índice da linha (y) primeiro.

3.3Tuplas

Em uma frase Como uma lista, mas imutável: depois de criada não muda.

Analogia Um par de coordenadas escrito a caneta: dá para ler, não dá para alterar.

entry = (0, 0)
x, y = entry                  # "desempacota" a tupla em duas variáveis
print(x, y, entry == (0, 0))
# entry[0] = 5   -> TypeError: tupla não aceita alteração
Saída
0 0 True

No projeto Coordenadas (x, y): entry, exit e as células do conjunto pattern_cells.

Erro comum Tentar alterar um item. Para "mudar", crie outra tupla.

Teste rápido: Por que tuplas podem estar dentro de um conjunto (set) e listas não?

Porque são imutáveis: um valor que não muda pode ser usado como "chave" de busca.

3.4Dicionários

Em uma frase Uma coleção de pares chave → valor.

Analogia Uma agenda de contatos: você procura pelo nome (chave) e obtém o telefone (valor).

pairs = {"WIDTH": "20", "HEIGHT": "15"}
pairs["PERFECT"] = "True"
print(pairs["WIDTH"], "SEED" in pairs, pairs.get("SEED", "nenhuma"))
Saída
20 False nenhuma

No projeto _read_pairs transforma o arquivo de configuração num dicionário; _DELTAS liga cada direção a (dx, dy).

Erro comum Pedir uma chave que não existe (pairs["SEED"]) dá KeyError. Use in ou .get().

Teste rápido: O que pairs.get("X", 0) devolve se não existe a chave X?

O valor padrão, 0, sem erro.

3.5Conjuntos (set)

Em uma frase Uma coleção sem repetidos, ótima para perguntar "este item está aqui?".

Analogia A lista de convidados na portaria: cada nome aparece uma vez e conferir é rápido.

visited = {(0, 0)}
visited.add((1, 0))
visited.add((1, 0))                  # repetido: ignorado
print(len(visited), (1, 0) in visited)
Saída
2 True

No projeto visited nos algoritmos de geração, on_path no desenho e pattern_cells (um frozenset, conjunto imutável).

Erro comum {} vazio é um dicionário, não um conjunto. Conjunto vazio é set().

Teste rápido: Por que usar set em vez de lista para as células visitadas?

Verificar se uma célula está num conjunto é quase instantâneo; numa lista grande é lento.

3.6Filas (deque)

Em uma frase Uma lista otimizada para tirar itens do começo: o primeiro a entrar é o primeiro a sair.

Analogia A fila do banco.

from collections import deque

queue = deque(["a", "b"])
queue.append("c")           # entra no fim
print(queue.popleft())      # sai do começo
print(list(queue))
Saída
a
['b', 'c']

No projeto A busca em largura (BFS) em MazeGenerator.solve_cells.

Erro comum Usar lista.pop(0) numa fila grande é lento; deque.popleft() é rápido.

Teste rápido: Fila e pilha tiram o item de onde?

Fila: do começo (FIFO). Pilha: do fim, o último que entrou (LIFO).

3.7List comprehension

Em uma frase Uma forma curta de criar uma lista a partir de outra, com filtro opcional.

Analogia "Separe só as peças vermelhas desta caixa" em uma frase.

pares = [n for n in range(10) if n % 2 == 0]
print(pares)
dobros = [n * 2 for n in range(4)]
print(dobros)
Saída
[0, 2, 4, 6, 8]
[0, 2, 4, 6]

No projeto options = [n for n in self._free_neighbours(x, y) if (n[0], n[1]) not in visited]: vizinhos ainda não visitados.

Erro comum Compressões muito longas ficam ilegíveis: nesse caso use um for normal.

Teste rápido: O que [c for c in "abc"] devolve?

['a', 'b', 'c'].

Módulo 4. Organizando o código

Como dividir um programa em pedaços reutilizáveis: funções, arquivos e pastas.

4.1Funções, parâmetros e return

Em uma frase Um bloco de código com nome, que recebe entradas (parâmetros) e devolve um resultado.

Analogia Uma máquina de suco: você coloca frutas (parâmetros) e ela devolve o suco (return).

def area(width, height):
    return width * height

print(area(20, 15))
Saída
300

No projeto format_maze(maze) recebe o labirinto e devolve o texto do arquivo; write_output grava esse texto.

Erro comum Esquecer o return: a função devolve None. Esquecer os parênteses: area é a função, area(2, 3) é o resultado.

Teste rápido: O que uma função sem return devolve?

None (nada).

4.2Valores padrão e argumentos nomeados

Em uma frase Um parâmetro pode ter valor padrão, e na chamada podemos escrever nome=valor.

Analogia Pedir um café: se você não disser nada vem "com açúcar" (padrão); você pode pedir "sem açúcar" pelo nome da opção.

def greet(name, punct="!"):
    return "Oi, " + name + punct

print(greet("Ana"))
print(greet("Bia", punct="?"))
Saída
Oi, Ana!
Oi, Bia?

No projeto MazeGenerator(width=20, height=15, perfect=True, seed=42): perfect vale False e algorithm vale "dfs" se você não disser nada.

Erro comum Usar uma lista vazia como valor padrão (def f(x=[])): ela é compartilhada entre chamadas. Prefira None.

Teste rápido: Por que perfect=True deixa a chamada mais legível?

Porque o nome explica o que o valor significa, sem precisar lembrar a ordem dos parâmetros.

4.3Módulos e import

Em uma frase Um módulo é um arquivo .py; import traz o que há nele para o seu arquivo.

Analogia Pegar emprestada uma ferramenta de outra caixa de ferramentas em vez de fabricá-la.

import random
from collections import deque

rng = random.Random(42)
fila = deque()
print(type(rng).__name__, type(fila).__name__)
Saída
Random deque

No projeto a_maze_ing.py faz from app.config import load_config e from mazegen import MazeGenerator.

Erro comum ModuleNotFoundError: pasta errada, pacote não instalado, ou um arquivo seu com o mesmo nome de um módulo padrão (por exemplo random.py).

Teste rápido: Qual a diferença entre import random e from random import Random?

O primeiro traz o módulo (usa-se random.Random); o segundo traz só o nome Random.

4.4Pacotes (pastas de módulos)

Em uma frase Uma pasta com um __init__.py que agrupa módulos relacionados.

Analogia Uma gaveta etiquetada que guarda várias pastas de documentos do mesmo assunto.

mazegen/
    __init__.py      # o que o pacote mostra para fora
    generator.py     # a classe MazeGenerator

10.4Recursão e o limite de recursão

Em uma frase Uma função que chama a si mesma. O Python limita isso a cerca de 1000 chamadas empilhadas.

print(countdown(100))
try:

except RecursionError:
    print("RecursionError: fundo demais")
Saída
fim
RecursionError: fundo demais

Teste rápido: Como evitar estourar o limite de recursão?

10.5DFS: o "recursive backtracker"

Em uma frase Anda por corredores novos até travar; ao travar, volta até achar uma bifurcação ainda inexplorada.

Analogia Explorar uma caverna com um fio de lã: avança e abre passagens; quando só há paredes, recolhe o fio até um ponto com saída.

# esqueleto (mazegen/generator.py: _carve_dfs)
visited = {entry}
stack = [entry]
while stack:
    x, y = stack[-1]                    # célula atual (topo da pilha)
    options = [n for n in neighbours(x, y) if n not in visited]
    if not options:
        stack.pop()                     # beco: volta um passo
        continue
    nx, ny, direction = rng.choice(options)
    open_wall(x, y, direction)          # derruba a parede
    visited.add((nx, ny))
    stack.append((nx, ny))              # avança

No projeto MazeGenerator._carve_dfs. O resultado é uma árvore geradora: conectada, sem ciclos, corredores longos e tortuosos. É o primeiro passo dos dois modos.

Erro comum Esquecer de marcar as células do "42" como indisponíveis: o algoritmo as abriria.

Teste rápido: Quando o DFS faz stack.pop()?

Quando a célula atual não tem nenhum vizinho novo: ele volta uma célula.

10.6Prim e Kruskal (outros algoritmos)

Em uma frase Prim cresce a partir de uma "borda" de paredes sorteadas; Kruskal junta ilhas de células com paredes sorteadas, sem formar ciclo.

Analogia Prim: uma mancha de tinta se espalhando. Kruskal: várias ilhas que vão ganhando pontes até virar um continente só.

# Kruskal em uma ideia (usa "union-find" para saber se duas
# células já estão na mesma ilha):
#   1) sorteie a ordem de todas as paredes entre células vizinhas
#   2) para cada parede: se as duas células estão em ilhas
#      diferentes, derrube a parede e una as ilhas
#   3) se já estão na mesma ilha, mantenha a parede (evita ciclo)

No projeto _carve_prim e _carve_kruskal, escolhidos pela chave ALGORITHM=prim|kruskal do config. Mudam o "jeito" do labirinto (Prim e Kruskal dão corredores curtos e muitas bifurcações); o resto é igual. É um dos bônus.

Erro comum Em Kruskal, esquecer de checar a ilha e criar ciclos num labirinto que deveria ser perfeito.

Teste rápido: O que os três algoritmos têm em comum?

Todos constroem uma árvore geradora: conectada e sem ciclos.

10.7BFS: o caminho mais curto

Em uma frase Explora o labirinto em "ondas", das células mais próximas às mais distantes; a primeira vez que chega ao destino é pelo menor caminho.

Analogia Uma pedra na água: as ondas se espalham por igual, e a primeira que toca a margem veio pelo trajeto mais curto.

# esqueleto (mazegen/generator.py: solve_cells)
parents = {entry: None}
queue = deque([entry])
while queue:
    cell = queue.popleft()               # o mais antigo da fila
    if cell == exit:
        break
    for neighbour in open_neighbours(cell):
        if neighbour not in parents:     # ainda não visto
            parents[neighbour] = cell    # "cheguei nele vindo de cell"
            queue.append(neighbour)
# reconstrói de trás para frente, do exit até a entry, seguindo parents

No projeto MazeGenerator.solve_cells e solve (que converte a lista de células em N/E/S/W). O caminho vai para a 3ª linha de dados do arquivo e para o destaque no menu: os dois vêm do mesmo cálculo, por isso batem.

Erro comum Usar DFS para resolver: acha um caminho, não necessariamente o mais curto.

Teste rápido: Para que serve o dicionário parents?

Guarda de onde se veio a cada célula, para reconstruir o caminho de trás para frente e para marcar as já vistas.

10.8Braiding: tirar os becos sem saída

Em uma frase Trançar o labirinto: para cada beco sem saída, derrubar uma parede para ligá-lo a outro corredor.

Analogia Abrir uma porta no fundo da rua sem saída, dando uma segunda saída.

# esqueleto (mazegen/generator.py: _braid)
for cell in dead_ends():                       # em ordem aleatória
    for neighbour in closed_walls_of(cell):    # prefere outro beco
        open_wall(cell, neighbour)
        if creates_3x3_open_area(cell, neighbour):
            close_wall(cell, neighbour)        # desfaz e tenta outra
            continue
        break                                  # deu certo: próximo beco

No projeto MazeGenerator._braid, só quando PERFECT=False. Cria laços (rotas alternativas, exigidas pelo modo jogável) sem nunca produzir área 3x3. É também o que dá o bônus "sem becos".

Erro comum Abrir paredes sem checar o 3x3: surgem salões, que o enunciado proíbe.

Teste rápido: Por que o braiding derruba uma parede e depois checa o 3x3, desfazendo se preciso?

Porque é simples tentar e conferir o resultado: a checagem olha a grade já com a parede aberta.

10.9Custo: quanto demora?

Em uma frase Medir como o tempo cresce quando o labirinto cresce (notação O).

Analogia Pintar uma parede: o dobro da parede dá o dobro do trabalho. Isso é O(n).

Roteiro da defesa

Cada integrante deve conseguir responder a tudo isto, com as próprias palavras e sem consultar. Os "testes rápidos" de cada conceito são o ensaio.

  1. Fluxo geral: o que acontece entre python3 a_maze_ing.py config.txt e o menu aparecer? (Início, passos 1 a 6.)
  2. Representação: o que significa o dígito A no arquivo? Como _open garante que as paredes coincidem? (Módulo 8.)
  3. Geração: explique o DFS iterativo com a pilha; por que não recursivo? (Módulo 10.)
  4. Modo jogável: o que é o braiding, por que a checagem 3x3 e por que sobram os becos do "2"? (Módulos 9 e 10.)
  5. Solução: como o BFS garante o caminho mais curto e como o caminho vira N/E/S/W? (Módulo 10.)
  6. Reprodução: o que a seed faz e por que usamos random.Random(seed)? (Módulo 10.)
  7. Erros: mostre o que acontece com cada erro de configuração e com Ctrl+C / Ctrl+D. (Módulo 6 e 11.)
  8. Pacote: como reconstruir o .whl num venv e instalar noutro? (Módulo 12.)
  9. Qualidade: rode make lint e make test e explique o que cada ferramenta checa. (Módulo 7.)
  10. Modificação surpresa: treine pequenas mudanças (trocar uma cor, adicionar uma chave de config, mudar o tamanho mínimo do "42") e rode os testes depois.
